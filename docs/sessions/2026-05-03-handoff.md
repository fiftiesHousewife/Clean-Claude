## Decisions worth preserving (don't relitigate)

1. **`@Override` is the right axis for "skip contract-mandated
   signatures"** (used by F2). Did NOT fold into
   `BoilerplateMethodSkip.isContractMethod` because other recipes (e.g.
   C3 mumbling) legitimately fire on `@Override` methods. Lives as
   `BoilerplateMethodSkip.isOverride` and is called explicitly from
   `OutputArgumentRecipe`.
2. **G33 fires on repetition, not on every `±1`**. The book's smell is
   the SAME boundary expression appearing twice. Single-use
   `items.size() - 1` / `lastIndexOf('/') + 1` is idiomatic.
3. **G34 = banner shape only**. Per `HEURISTICS.md`, G34 is `// ===
   section ===` style markers. Long explanatory comments are
   documentation, not banners. Threshold raised from 1 → 2.
4. **G31 same-receiver-and-method key, via printTrimmed**.
   `Expression.toString()` includes AST internals — two textually
   identical chains still produced different keys. Use
   `select.printTrimmed(getCursor())` for a stable source-form key.
5. **G35 trivial floor = 4**. `2`/`3`/`4` are nearly always indices.
   Real magic numbers (60s, 100%, 120 cols, 1000ms) are still caught.
6. **N1 skips suffix when supertype shares it**. `ReportHandler
   implements HttpHandler` is contract-mandated — the user can't rename
   without breaking the supertype.
7. **Ch7.2 doesn't count `Objects.requireNonNull`**. It's the
   recommended fail-fast pattern, not a smell.
8. **C2 needs mixed-case + length ≥ 3**. Filters acronyms (`MCP`,
   `HTML`, `URL`) without needing a project-wide class index.

### Backlog — additional finding sources (added 2026-05-04)

User-proposed signals that would catch code-quality issues the current
PMD/Checkstyle/SpotBugs/CPD/OpenRewrite pipeline misses. Ranked by value:

1. **PIT (`info.solidsoft.pitest`) → T1 Insufficient Tests.** Mutation
   kill-rate is the actual T1 signal — "which production lines can be
   silently broken without a test failing." Strictly better than the
   current threshold-driven `privateMethodMinLines` heuristic. PIT writes
   `build/reports/pitest/mutations.xml`; the plugin can parse it for
   per-class survival rate and roll into T1.
2. **Error Prone + NullAway (`net.ltgt.errorprone` + `nullaway`) →
   Ch7.2 Don't Return Null + dozens of "real bug" patterns.** Runs as a
   javac plugin so it's nearly free. Catches concurrency, immutability,
   generics misuse, null-flow — `clean-code-null-handling` skill exists
   but nothing currently enforces it. Easiest integration path: scrape
   `compileJava` output, or convert via a SARIF reporter.
3. **ArchUnit (test-dep, no plugin) → Ch10.2 SRP, G14 Feature Envy,
   G17 Misplaced Responsibility.** This project's `CLAUDE.md` declares
   architectural rules ("helpers package-private not private", "break
   complex visitor methods into named helpers") that PMD/Checkstyle
   can't see. ArchUnit turns them into JUnit assertions; the plugin
   already aggregates JaCoCo, so reading JUnit XML is consistent.
4. **Modernizer (`com.github.andygoossens.gradle-modernizer-plugin`) →
   G24 Follow Standard Conventions, J1, J3.** Catches outdated APIs
   (`new Boolean(...)`, `Collections.synchronizedList`, raw Date
   arithmetic). Tiny config, near-zero false positives. Native Gradle
   XML/text report.
5. **Forbidden APIs (`de.thetaphi.forbiddenapis`) → G4 Overridden
   Safeties.** Prevents regression to banned APIs (default-locale
   `toLowerCase`, `Random` in non-test paths, `System.out` — relevant
   given this project's raison d'être). Native Gradle report.

If forced to pick two: PIT (makes T1 honest) and Error Prone + NullAway
(catches a class of bug the current pipeline simply doesn't see).
ArchUnit is the third if the plan is to enforce CLAUDE.md's
architectural rules rather than have them be aspirational.

## Known recipe limitations to keep in mind

1. **`MagicStringRecipe` / G5 short-format filter** is permissive: it
   only filters strings that have ZERO letters or digits AND length ≤
   5. So `"%.4f"` (has `4` and `f`) still fires. Acceptable for now —
   `"%.4f"` arguably IS a real magic format string. Tighten only if
   real users complain.
2. **`G31 TemporalCouplingRecipe` distinct-call key** uses
   `printTrimmed(getCursor())`. If the same chain has different
   whitespace formatting in two places, the keys won't match and they
   register as distinct. In practice formatters normalise this; not
   worth chasing unless we see false positives.
3. **`G33 BoundaryConditionRecipe` per-method state** uses a
   non-thread-safe `HashMap` field on the visitor. OpenRewrite visitors
   are single-threaded per file but if that ever changes, the recipe
   needs synchronisation.
4. **`C2 ObsoleteCommentRecipe` `looksLikeAJavaIdentifier`** rejects
   tokens shorter than 3 characters or all-uppercase. So `Map`, `id`
   are rejected too. Acceptable — short tokens are too noisy as
   prose-vs-code signals.

## Backlog — logging anti-patterns (added 2026-05-04)

User-proposed expansion of the logging recipe set. Architectural rule
established this session: **a single recipe per mechanical/always-safe
pattern, with dry-run output as the finding stream**. Only split into
detect-only vs fix when (a) the fix is one of several structural
choices or (b) the smell is legitimately tolerable in some places.

### Tier 1 — High-value mechanical fixes (single recipe each)

1. **Parameterize string-concat log calls.** `log.info("User " + id +
   " created")` → `log.info("User {} created", id)`. Same machinery as
   the existing `System.out` recipe, retargeted at SLF4J. **Probably
   the single highest-value addition.**
2. **Throwable as last argument with no placeholder.**
   `log.error("failed: {}", e)` → `log.error("failed", e)` so the
   stack trace is preserved. Plus the Log4j-style `log.error(e, msg)`
   ordering mistake. Cheap to detect, real bugs.
3. **`log.error("...: " + e.getMessage())` → pass the Throwable
   directly.** Loses stack trace today; very common; one of the most
   under-reported "real bugs in real code".
4. **Apache Commons Logging → SLF4J.** Same shape as existing
   `JulToSlf4jRecipe`, different source framework. Lots of legacy
   Java codebases still on commons-logging.
5. **Direct `org.slf4j.Logger` field → `@Slf4j`.** Generalisation of
   the existing `ConvertManualLoggerToSlf4j` recipe (Log4j2-only) to
   any SLF4J Logger declaration.
6. **`Throwable.printStackTrace(PrintStream)` → `log.error(throwable)`.**
   The lesser-known sibling of `e.printStackTrace()`. Same fix shape.

### Tier 2 — Logger hygiene

1. **Static logger field.** `Logger log = LoggerFactory.getLogger(...)`
   (instance) → `private static final Logger log = ...`. High signal
   but most projects already do this; useful in legacy code.
2. **Inconsistent logger field naming.** `LOGGER` / `LOG` / `log` →
   project standard (default to `log` since `@Slf4j` produces it).
   Configurable via `@Option`.
3. **Remove unused logger field.** After migration recipes run.
   Partial form already exists for JUL imports.
4. **Disallow `System.console()` in non-CLI code.** Same family as
   `System.out`; opt-in because CLI tools legitimately use it.

### Tier 3 — Anti-patterns (correctness, real bugs)

These are **detect-only** by default — a fix recipe ships separately
because users may legitimately want to keep the pattern in some
places.

1. **Empty catch block** — flag and suggest `log.warn` / rethrow.
   False positives on test code; configure exclusions.
2. **Log-and-throw** — `log.error(...); throw e;` is double-reporting.
   Strong opinion; might surprise users who like both. Worth an
   `@Option` to disable.
3. **MDC put without remove** — flag `MDC.put` without a corresponding
   `MDC.remove` or `MDCCloseable` try-with-resources. Catches a real
   production bug class (cross-request log pollution).

### Tier 4 — Configuration & infrastructure

1. **Logback / log4j2 XML normalisation.** Async appenders, sensible
   patterns, JSON encoder for cloud, file rotation defaults. Easier
   as a template generator than as transformation rules — XML is
   gnarly.
2. **`@Option` to pick `@Slf4j` vs `@Log4j2` vs `@Flogger` on existing
   recipes.** Today there are separate recipes per backend;
   consolidating with an option cleans up the public surface.
